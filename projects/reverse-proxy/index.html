Nginx Reverse Proxy

A central reverse proxy on a Linux VPS: several containerized sites behind one public IP, routed by subdomain, with automatic SSL/TLS.

01 Overview

One public IP hosts several web services, including a game and personal portfolio sites. TLS is handled in one place, and the internal addresses and ports of the backends stay hidden.

02 Architecture

Nginx acts as the traffic controller: each request is sent to the right container based on its subdomain. Each service runs in its own Docker container.

03 Implementation

One server block per subdomain with proxy_pass to the container, and Let's Encrypt certificates for automatic HTTPS on every subdomain.

04 Troubleshooting

The subdomains weren't reachable from my machine even though everything looked healthy. I checked the container status and port mappings, validated the config with nginx -t and looked at name resolution. The cause was browser-level HTTPS enforcement: Chrome and Brave refuse plain HTTP for some domains or cached HSTS settings. Running Certbot for each subdomain before loading it, so Nginx listened on 443 with valid certificates, fixed it.

05 Result

Several applications on a single IP, full TLS on every public service, and internal IPs and ports not exposed.
