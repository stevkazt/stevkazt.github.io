Thesis · Research

AI-built, human-directed

SGVA

My Telecommunications Engineering thesis: how the architectural quality of a system changes when a generative AI writes most of the code.

01 The question

How does continuous use of generative AI, prioritising functional correctness, change dependency-rule compliance and technical debt in iterative development under Clean Architecture?

  • TitleAnalysis of architectural quality and technical debt in a system developed under Clean Architecture with generative AI assistance
  • AuthorJohann Stev Castellanos Gonzalez
  • UniversityUniversidad Santo Tomás (USTA), Bogotá · 2026
  • StatusThesis wrapping up, December 2026

02 Method

I built a real system (SGVA, in Kotlin and Spring Boot) under Clean Architecture, with Claude Code as the main assistant: a manual baseline plus six iterations, growing from 10 to 3,875 lines of code. At the end of each prompt I measured the system with two instruments:

SonarQubeArchUnitKotlinSpring BootClaude Code
  • SonarQubeOne server and quality profile: 21 measurements. Key indicator: technical debt ratio.
  • ArchUnitDependency rules written by hand before the AI phase; a violation in domain or use cases is a critical break.
  • StressTwo deliberate technology changes: relational persistence (V3) and PDF reports (V4).

03 Results and conclusions

  • Tech debtThe ratio fell from 3.3 % in the manual baseline to 0.4 % at the first prompt and stayed between 0.0 % and 0.1 %, with grade A in all 21 measurements.
  • RulesArchUnit's dependency rules were green throughout the series. The suite failed four times in V1, on a naming convention, and the agent adapted the code without touching the rules.
  • StressThe relational database and the PDF library stayed confined to infrastructure, with no change in the debt ratio and no ArchUnit failure.

With these measurements there is no progressive increase in debt or in dependency violations. That does not refute the hypothesis: the agent could see the ArchUnit suite during the session, and the instruments don't measure everything, for example coupling between infrastructure components. The conclusions describe what happened with that instrumentation visible; testing them needs a replication without that feedback.

Chapters are still drafts; results may change before the final submission.
